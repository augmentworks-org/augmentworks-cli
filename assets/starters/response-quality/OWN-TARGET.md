# Own-target workflow (response-only JSON chat)

This directory is generated by `init` (starter `response-quality`, aliases
`response-only` and `chat`). It is synthetic test data, not a production FAQ.
Hosted real-data quote and admission stay release-disabled. Do not point this
fictional starter at production customer records. This text is not legal
approval.

Streaming, WebSocket, history-array multi-turn, and connector marketplaces are
not supported. The only JSON HTTP patterns in this CLI are response-only chat
and the stateful `workflow` starter.

This 0.3.8 package generates these files and includes `probe`. Do not pin
immutable npm `0.3.3`. Invoke the CLI as `{{AW_CLI}}` below.

## Files

| File | Role |
| --- | --- |
| `augmentworks.yaml` | Response-only send mapping. No prepare/observe/cleanup. |
| `augmentworks.session.yaml` | Same chat endpoint with `explicit_session_v1`. |
| `augmentworks.assessment.yaml` | Hosted `response-quality@0.1.0` assessment. |
| `own-chatbot.suite.yaml` | Five customer-authored synthetic FAQ cases. |
| `references/` | Expected facts for the five suite cases. `old-returns.md` is a stale catalog extract and is not attached to the suite; mixed 14-day/30-day windows are refused before quote. |
| `fixtures/send-response.json` | Offline mapping-preview fixture. |
| `server.mjs` | Dual-mode FAQ fixture (session optional). |
| `session-server.mjs` | Session-required fixture. |

## Commands

```bash
# Edit the local .env that init created or preserved.
# Do not run `cp .env.example .env` after init: that overwrites a preserved file.
# If you passed --no-env and .env is missing:
[ -f .env ] || cp .env.example .env
# Windows: if not exist .env copy .env.example .env
# Set CHATBOT_API_KEY locally. Never commit .env.

node --env-file=.env server.mjs

{{AW_CLI}} doctor -c augmentworks.yaml
{{AW_CLI}} preview-mapping -c augmentworks.yaml --operation send --fixture ./fixtures/send-response.json
{{AW_CLI}} probe -c augmentworks.yaml
{{AW_CLI}} probe -c augmentworks.yaml --yes
{{AW_CLI}} suite validate own-chatbot.suite.yaml
{{AW_CLI}} suite preview own-chatbot.suite.yaml
{{AW_CLI}} test --assessment ./augmentworks.assessment.yaml --estimate
{{AW_CLI}} test --suite own-chatbot.suite.yaml --estimate
```

`doctor` and `init` never probe. `probe` without `--yes` only prints the plan.
`probe --yes` calls the mapped endpoints with synthetic correlation ids and
does not contact AugmentWorks or consume credits. Hosted `test` still needs
`--max-credits N --yes`. npm `--yes` is not a spending ceiling.

Session mapping:

```bash
node --env-file=.env session-server.mjs
{{AW_CLI}} doctor -c augmentworks.session.yaml
{{AW_CLI}} probe -c augmentworks.session.yaml --yes
```

After a hosted run, inspect with `run status` / `run wait` / `run report` on
the original run id. Cleanup for this pattern is a chat-only target: stop the
fixture process. A hard kill can skip application-side cleanup; keep a
server-side TTL on real targets.
